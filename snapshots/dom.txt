> **But de ce document** : permettre à un nouveau modèle Claude de reprendre exactement
> là où la session précédente s'est arrêtée, sans perte de contexte.
> À coller en début de conversation avec le fichier `playwright_launcher.py` en pièce jointe.

---

## 1. Contexte projet

SurveyBot est un système Python/Selenium qui complète des sondages en ligne de façon automatisée
à grande échelle (~100 bots concurrents). Chaque bot tourne sur Fly.io (Xvfb + Chrome headless),
avec un proxy ISP dédié (IPRoyal). L'objectif est de passer les vérifications anti-bot des
plateformes de sondage, notamment **Sentry/CloudResearch**, qui sont parmi les plus strictes.

Le fichier central pour cette tâche est :
**`preselection/playwright_launcher.py`**

Ce fichier lance Chrome via `subprocess.Popen`, attache Selenium via `--remote-debugging-port`,
puis injecte du JS de spoofing fingerprint via `Page.addScriptToEvaluateOnNewDocument` (CDP).

---

## 2. Problème constaté

En prod (Fly.io), les bots sont **immédiatement redirigés vers TopSurveys** dès l'ouverture
de la page d'entrée Sentry (`/entry/...`), sans voir une seule question de sondage.
C'est une disqualification silencieuse côté plateforme, déclenchée par la détection du bot
sur la page d'entrée.

### Preuve : comparaison BrowserLeaks prod vs attach

Le mode **attach** (Chrome Windows, référence) est utilisé pour tester manuellement.
Le mode **prod** (Chrome Linux/Xvfb Fly.io) est celui qui se fait détecter.

| Signal | Mode attach (référence ✅) | Mode prod (détecté ❌) |
|--------|--------------------------|----------------------|

## 3. Analyse des causes

### 3.1 `deviceMemory = 1` — Signal #1 (critique)

**Cause** : Le code `_fingerprint_js()` contient bien `{ get: () => 8 }` ligne ~514,
MAIS `Page.addScriptToEvaluateOnNewDocument` n'est actif que pour les navigations *futures*.
Si le profil Chrome persisté charge une page au démarrage, ou si la page BrowserLeaks
est déjà chargée au moment de l'inject, la valeur `1` (défaut Linux headless) est exposée.

**Fix requis** : En plus du `addScriptToEvaluateOnNewDocument`, appliquer les patches
critiques (`deviceMemory`, `webdriver`, `cdc_*`) en `execute_script` synchrone immédiat
juste après l'attach Selenium — **ce patch synchrone existe déjà dans le code pour
`webdriver` et `cdc_*`, mais `deviceMemory` n'y est pas inclus**. L'ajouter.

### 3.2 `uaFullVersion = "148.0.0.0"` — Signal #2 (fort)

**Cause** : Dans `_fingerprint_js()`, la fonction `getHighEntropyValues` retourne
`uaFullVersion: '148.0.0.0'` (valeur hardcodée ronde). Les SDK anti-bot modernes
appellent `navigator.userAgentData.getHighEntropyValues(['uaFullVersion'])` et
rejettent les versions rondes comme signal de spoofing évident.

Un vrai Chrome 148 retourne `148.0.7776.219`. Un vrai Chrome 149 retourne `149.0.7776.x`.

**Fix requis** : Lire dynamiquement la version majeure du Chrome lancé (via
`_detect_chrome_major_version()` qui existe déjà dans le code), puis construire une
`uaFullVersion` réaliste. La fonction `_detect_chrome_major_version()` est déjà
présente dans `playwright_launcher.py` — il faut passer la version au JS via une
interpolation de string dans `_fingerprint_js(version)`.

Les versions complètes réelles à utiliser :
- Chrome 148 → `148.0.7776.219`
- Chrome 149 → `149.0.7776.219` (à confirmer, ou lire depuis le binaire)

### 3.3 `screen.colorDepth = 24` vs `32` — Signal #3 (mineur)

**Cause** : `_fingerprint_js()` force `colorDepth` et `pixelDepth` à `24` (ligne ~507-508).
Le mode attach Windows retourne `32`. La valeur `32` est standard sur Windows 10/11.

**Fix requis** : Changer `24` → `32` pour `colorDepth` et `pixelDepth` dans `_fingerprint_js()`.

### 3.4 `WebGL Report Hash` différent — Signal #4 (fort)

**Cause** : Le hash est calculé sur le dump JSON complet de tous les paramètres WebGL.
Malgré les nombreux overrides déjà en place dans `_glProxy`, un ou plusieurs paramètres
retournent encore des valeurs SwiftShader au lieu des valeurs Intel UHD 617 cibles.

Les candidats non couverts ou mal alignés (à vérifier en comparant les JSON Dumps
BrowserLeaks des deux modes) :
- `MAX_DRAW_BUFFERS_WEBGL` (extension `WEBGL_draw_buffers`)
- `MAX_COLOR_ATTACHMENTS_WEBGL`
- `MAX_SAMPLES` (WebGL2)
- Paramètres d'extensions non standard couverts par le dump BrowserLeaks

**Fix requis** : Comparer les deux JSON Dumps WebGL (bouton "JSON Dump" sur BrowserLeaks)
entre prod et attach, identifier les valeurs divergentes, et les ajouter au `_glProxy`
existant avec les valeurs Intel UHD 617.

**Contrainte importante** : `WebGL Image Hash` (rendu visuel du triangle) **ne peut pas**
être spoofé — SwiftShader et GPU réel produisent des pixels différents. Les SDK anti-bot
sérieux (dont Sentry) se basent sur le **Report Hash** (paramètres), pas l'Image Hash.
Ne pas tenter de spoofer l'Image Hash.

## 5. Fixes à implémenter (par ordre de priorité)

### Fix 1 — `deviceMemory` dans le patch synchrone (5 min)

Dans `apply_fingerprint_overrides_cdp()`, le bloc `driver.execute_script(...)` synchrone
applique déjà `webdriver` et `cdc_*`. Ajouter `deviceMemory` et `hardwareConcurrency`
dans ce même bloc :

```javascript
// Ajouter dans le execute_script synchrone existant :
try {
    Object.defineProperty(navigator, 'deviceMemory', { get: () => 8 });
    Object.defineProperty(navigator, 'hardwareConcurrency', { get: () => 4 });
} catch(e) {}
```

### Fix 2 — `screen.colorDepth` (2 min)

Dans `_fingerprint_js()`, changer :
```javascript
// Avant :
Object.defineProperty(screen, 'colorDepth', { get: () => 24 });
Object.defineProperty(screen, 'pixelDepth',  { get: () => 24 });

// Après :
Object.defineProperty(screen, 'colorDepth', { get: () => 32 });
Object.defineProperty(screen, 'pixelDepth',  { get: () => 32 });
```

### Fix 3 — `uaFullVersion` dynamique (15 min)

1. Modifier `_fingerprint_js()` pour accepter un paramètre `chrome_version: int` :
   `def _fingerprint_js(chrome_version: int = 148) -> str:`

2. Construire `uaFullVersion` à partir de la version :
   ```python
   # Map version majeure → version complète réelle connue
   _UA_FULL_VERSIONS = {
       148: "148.0.7776.219",
       149: "149.0.7776.219",
       # ajouter au fil des mises à jour Chrome
   }
   ua_full = _UA_FULL_VERSIONS.get(chrome_version, f"{chrome_version}.0.0.0")
   ```

3. Interpoler dans le JS :
   ```python
   uaFullVersion: '{ua_full}',
   fullVersionList: [
       {{ brand: 'Chromium',      version: '{ua_full}' }},
       {{ brand: 'Google Chrome', version: '{ua_full}' }},
       {{ brand: 'Not-A.Brand',   version: '99.0.0.0'  }},
   ],
   ```

4. Dans `apply_fingerprint_overrides_cdp(driver)`, détecter la version et passer :
   ```python
   chrome_bin = _detect_chrome_binary()
   chrome_ver = _detect_chrome_major_version(chrome_bin) or 148
   source = _fingerprint_js(chrome_version=chrome_ver)
   driver.execute_cdp_cmd("Page.addScriptToEvaluateOnNewDocument", {"source": source})
   ```

   Note : `_detect_chrome_major_version()` est déjà définie dans le fichier (~ligne 647).

### Fix 4 — WebGL Report Hash (30 min — nécessite JSON Dump BrowserLeaks)

**Pré-requis** : obtenir les deux JSON Dumps WebGL (bouton "JSON Dump" sur BrowserLeaks)
en mode attach et en mode prod, les comparer, identifier les paramètres divergents.

Sans les JSON Dumps, Claude Code ne peut pas savoir exactement quels paramètres manquent.
Fournir les deux fichiers JSON à Claude Code avec le prompt suivant.

## 7. Comment obtenir les JSON Dumps WebGL pour le Fix 4

1. En mode **attach** (Chrome Windows, référence) : ouvrir BrowserLeaks WebGL Report,
   cliquer "JSON Dump", sauvegarder `webgl_attach.json`.
2. En mode **prod** (Fly.io ou LOCAL_UNATTENDED=1) : idem, sauvegarder `webgl_prod.json`.
3. Comparer les deux fichiers (diff ou outil de comparaison JSON).
4. Lister les clés dont les valeurs diffèrent.
5. Fournir cette liste dans le Prompt Fix 4 à la place de `[INSÉRER ICI...]`.
