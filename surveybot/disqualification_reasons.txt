    explicables (version Chrome plus récente en prod). Piste close.

[4] TCP/IP Stack fingerprint
    Verdict : NON — piste écartée

    Pas de fuite vers Fly.io, pas de discordance ISP/DNS.
      - IP visible prod : 178.210.254.157 (proxy IPRoyal) ✅
      - ISP : Orange S.A., France Paris ✅
      - DNS : Cloudflare France Paris (43–45 serveurs) ✅

[6] TLS fingerprint / Akamai HTTP/2
    Verdict : PARTIEL — JA4 identique, JA3 diverge, ECH absent en prod
    Justification :
      - JA4  : t13d1516h2_d8aaf6152771_d8a2da3f94cd ✅ IDENTIQUE
      - JA4_o: attach ac858a92679_1e49fde2599b /
               prod   ac858a92679_f34fad98123f 🟡 delta mineur
      - JA3  : attach 458acd1b3217e8519e33bff22a9975b8d /
               prod   1429a2e3d95d08a8d5adcad4a2d8c25 🔴 diverge
      - ECH  : attach True / prod False 🔴 (proxy ne supporte pas ECH)
      - Akamai HTTP/2 : 1:65536;2:0;4:6291456;6:262144|15663105|0|m,a,s,p ✅
      - Akamai Hash   : 52d84b11737d980aef856699f885ca86 ✅

    ECH False est un signal mineur — le proxy IPRoyal ne supporte pas ECH,
    identique en attach et prod avec proxy actif. Non actionnable.
    Piste considérée acceptable — pas de correction envisagée.

[7] Client Hints HTTP (sec-ch-ua-platform, sec-ch-ua, sec-ch-ua-mobile)
    Verdict : CORRIGÉ ✅ — validé en prod le 2026-06-17
    Cause racine : Emulation.setUserAgentOverride échouait avec
    "invalid argument: Invalid parameters" (Chrome 149) — type incorrect
    sur le champ "wow64". Après correction :
      - sec-ch-ua-platform : "Windows" ✅
      - sec-ch-ua          : "Google Chrome";v="149", "Chromium";v="149",
                             "Not)A;Brand";v="24" ✅
      - sec-ch-ua-mobile   : ?0 ✅
      - userAgentData.brands (JS) : Chrome/149 ✅
    Résidu mineur : accept-language "en-US,en;q=0.9;q=0.9" (doublon q=0.9).
