[P1 — CRITIQUE] Client Hints HTTP absents en prod
    Statut : CONFIRMÉ EN PROD — à corriger en priorité absolue
    Symptôme : les trois headers Client Hints low-entropy sont totalement absents
    des requêtes HTTP en prod, alors qu'ils sont présents en attach.
    Comparaison HTTP/2 headers prod vs attach :
      - sec-ch-ua-platform : ABSENT en prod | "Windows" en attach 🔴
      - sec-ch-ua          : ABSENT en prod | "Google Chrome";v="149"... en attach 🔴
      - sec-ch-ua-mobile   : ABSENT en prod | ?0 en attach 🔴
    Ces trois headers sont Low Entropy — Chrome les envoie automatiquement sur
    chaque requête sans opt-in serveur. Leur absence totale indique que
    Emulation.setUserAgentOverride est appelé en prod SANS le paramètre
    userAgentMetadata, ce qui supprime l'émission automatique des Client Hints.
    Impact : tout anti-bot vérifiant la cohérence UA / Client Hints détecte
    immédiatement l'anomalie — un Chrome réel envoie toujours ces headers.
    Valeurs attendues (référence attach Chrome 149) :
      - sec-ch-ua          : "Google Chrome";v="149", "Chromium";v="149",
                             "Not)A;Brand";v="24"
      - sec-ch-ua-mobile   : ?0
      - sec-ch-ua-platform : "Windows"
    High Entropy (sur demande serveur via Accept-CH) — aussi à aligner :
      - platformVersion    : 19.0.0
      - architecture       : x86
      - bitness            : 64
      - wow64              : false
      - uaFullVersion      : 149.0.7827.103
      - fullVersionList    : Google Chrome 149.0.7827.103, Chromium 149.0.7827.103,
                             Not)A;Brand 24.0.0.0
      - formFactors        : ["Desktop"]
    Correction : appeler Emulation.setUserAgentOverride avec userAgentMetadata
    complet dans apply_fingerprint_overrides_cdp() (playwright_launcher.py).

[P2 — HAUTE] WebRTC IP leak
    Statut : NON VÉRIFIÉ EN PROD
    Hypothèse : WebRTC expose l'IP réelle de la machine Fly.io en plus de l'IP proxy.
    Valeurs attach (référence — propre) :
      - WebRTC Leak Test  : No Leak
      - Local IP Address  : - (aucune IP locale exposée)
      - Public IP (WebRTC): 176.186.86.39 (= IP proxy, cohérent)
      - SDP Log           : IN IP4 127.0.0.1 uniquement
    En prod, risque que le SDP expose l'IP interne Fly.io (fdaa::/7 ou 172.x.x.x)
    ou l'IP publique CDG Fly.io à côté de l'IP proxy.
    Correction envisagée : désactiver WebRTC via CDP ou flag Chrome.

[P3 — HAUTE] DNS leak
    Statut : NON VÉRIFIÉ EN PROD
    Hypothèse : Chrome résout les DNS via les resolvers Fly.io/Cloudflare au lieu
    des DNS du proxy IPRoyal, créant une incohérence IP/DNS détectable.
    Valeurs attach (référence — propre) :
      - IP visible    : 176.186.86.39 (proxy IPRoyal)
      - ISP visible   : BOUYGUES Telecom, France Paris
      - DNS Server 1  : 89.85.114.32 — Bouygues Telecom ISP — France, Paris
      - DNS Server 2  : 2001:860:de02::4 — Bouygues Telecom ISP Wireline — France, Paris
    En prod, risque que les DNS resolvent via Fly.io (fdaa::3) ou Cloudflare (1.1.1.1)
    pendant que l'IP de sortie reste IPRoyal → discordance ISP/DNS flagrante.
    Correction envisagée : forcer les DNS via le proxy dans la config Chrome/réseau.

[P4 — MOYENNE] Font fingerprint
    Statut : NON VÉRIFIÉ EN PROD
    Hypothèse : les fonts système Linux (prod) sont radicalement différentes
    des fonts Windows (attach), produisant un fingerprint distinct.
    Valeurs attach (référence) :
      - Font Metrics Hash  : 0837BB3621C61348A431BF30700830CE
      - Fonts détectées    : 213 fonts, 171 métriques uniques
      - Fonts Windows clés : Segoe UI, Segoe UI Variable Text, Arial, Helvetica,
                             Consolas, Comic Sans MS, Impact
      - Unicode Glyphs Hash: 1C9F7677
    En prod : absence totale de fonts Windows → hash radicalement différent.
    Priorité modérée : les panels font rarement du font fingerprinting actif.
