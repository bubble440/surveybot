[1] IP signalée comme "VPN" sur BrowserLeaks
    Verdict : NON — piste écartée
    Justification : les mêmes IPs IPRoyal ISP utilisées en mode local (attach)
    ne produisent aucune disqualification. La classification VPN n'est donc pas
    le facteur déclenchant.
    IP concernée documentée : 185.134.194.152

[2] Divergence fingerprint WebGL prod vs attach
    Verdict : NON — piste écartée
    Justification : le spoofing WebGL a été audité en profondeur (dump JSON
    complet prod vs attach, comparaison paramètre par paramètre).
    Résultat de l'audit :
      - Paramètres numériques WebGL1 : identiques (0 divergence)
      - Paramètres numériques WebGL2 : identiques sauf 4 params absents du
        dump attach car l'ancien script ne les mesurait pas
        (MAX_ELEMENTS_INDICES, MAX_ELEMENTS_VERTICES, MAX_ELEMENT_INDEX,
        MAX_SERVER_WAIT_TIMEOUT) — valeurs standard, non suspectes
      - Extensions WebGL2 : identiques
      - Extensions WebGL1 : 3 extensions supplémentaires en prod
        (EXT_render_snorm, EXT_texture_norm16, WEBGL_provoking_vertex) —
        présentes en prod car Chrome 148 / ANGLE plus récent que l'attach de
        référence ; avoir plus d'extensions n'est pas un signal de détection
      - HIGH_FLOAT_HIGH_INT : highp/highp dans les deux modes ✅
      - UNMASKED_VENDOR/RENDERER : "Google Inc. (Intel)" /
        "ANGLE (Intel, Intel(R) UHD Graphics 617 ...)" identiques ✅
      - Hash BrowserLeaks différent : artefact dû aux 4 params supplémentaires
        intégrés dans le calcul de hash côté BrowserLeaks — non significatif
    Note technique : le dump [FP][BROWSER] loggé au démarrage affichait
    userAgentData vide (brands=[], platform="") — c'était un artefact de
    lecture avant navigation (Page.addScriptToEvaluateOnNewDocument non encore
    actif sur la page courante). Corrigé en déplaçant le dump après une
    navigation about:blank. Le spoofing est bien actif sur toutes les pages
    réelles visitées.

[4] TCP/IP Stack fingerprint
    Verdict : NON — piste écartée
    Justification : le profil TCP/IP prod avec proxy actif est quasi-identique
    à l'attach avec proxy actif. Le fingerprint observé est celui du tunnel
    proxy IPRoyal (OpenVPN TCP bs128 SHA1 lzo), identique dans les deux modes.
    Valeurs attach + proxy (référence correcte) :
      - JA4T : 43080_2-4-8-1-3_1300_12, Satori "no matches", TTL 64, MTU 1340
    Conclusion : pas un vecteur de détection différentielle.

[6] Client Hints HTTP (sec-ch-ua-platform, sec-ch-ua, sec-ch-ua-mobile)
    Verdict : CORRIGÉ ✅ — validé en prod le 2026-06-17
    Cause racine : Emulation.setUserAgentOverride échouait avec "invalid argument:
    Invalid parameters" (Chrome 149) à cause d'un type incorrect sur le champ
    "wow64" (booléen Python au lieu du type attendu par le schéma CDP).
    Après correction du patch dans apply_fingerprint_overrides_cdp() :
      - sec-ch-ua-platform : "Windows" ✅
      - sec-ch-ua          : "Google Chrome";v="149", "Chromium";v="149",
                             "Not)A;Brand";v="24" ✅
      - sec-ch-ua-mobile   : ?0 ✅
      - userAgentData.brands (JS) : Chrome/149 ✅
    Résidu mineur : accept-language affiche "en-US,en;q=0.9;q=0.9" (doublon
    q=0.9) — à corriger dans le paramètre acceptLanguage de l'appel CDP.

[P1 — HAUTE] WebRTC IP leak
    Statut : NON VÉRIFIÉ EN PROD
    Hypothèse : WebRTC expose l'IP réelle de la machine Fly.io en plus de l'IP proxy.
    Valeurs attach (référence — propre) :
      - WebRTC Leak Test  : No Leak
      - Local IP Address  : - (aucune IP locale exposée)
      - Public IP (WebRTC): 176.186.86.39 (= IP proxy, cohérent)
      - SDP Log           : IN IP4 127.0.0.1 uniquement
    En prod, risque que le SDP expose l'IP interne Fly.io (fdaa::/7 ou 172.x.x.x)
    ou l'IP publique CDG Fly.io à côté de l'IP proxy.
    Correction envisagée : désactiver WebRTC via CDP ou flag Chrome.

[P2 — HAUTE] DNS leak
    Statut : NON VÉRIFIÉ EN PROD
    Hypothèse : Chrome résout les DNS via les resolvers Fly.io/Cloudflare au lieu
    des DNS du proxy IPRoyal, créant une incohérence IP/DNS détectable.
    Valeurs attach (référence — propre) :
      - IP visible    : 176.186.86.39 (proxy IPRoyal)
      - ISP visible   : BOUYGUES Telecom, France Paris
      - DNS Server 1  : 89.85.114.32 — Bouygues Telecom ISP — France, Paris
      - DNS Server 2  : 2001:860:de02::4 — Bouygues Telecom ISP Wireline
    En prod, risque que les DNS resolvent via Fly.io (fdaa::3) ou Cloudflare
    pendant que l'IP de sortie reste IPRoyal → discordance ISP/DNS flagrante.

[P3 — MOYENNE] Font fingerprint
    Statut : NON VÉRIFIÉ EN PROD
    Valeurs attach (référence) :

      - Fonts détectées    : 213 fonts, 171 métriques uniques
      - Fonts Windows clés : Segoe UI, Segoe UI Variable Text, Arial, Helvetica,
                             Consolas, Comic Sans MS, Impact
      - Unicode Glyphs Hash: 1C9F7677

[P4 — BASSE] Features browser hardware-dependent
